# Experimental strategy and shadow trading

The Experimental strategy is `trend-pullback-v1`. It waits for the 1h EMA trend and ADX to agree, rejects very low or high 1h ATR%, and checks the direction of the 30m EMA trend. The 5m trigger is a pullback into its fast EMA followed by a close past the previous bar in the trend direction. Risk uses ATR on complete 15m bars through the bar before the trigger, with a stop beyond the 5m swing if the existing stop-distance limit permits it. The strategy applies identical long and short rules by sign. It rejects absent or anomalously high volume and a trigger that has already moved too far from its EMA. It skips range and extreme volatility regimes.

The current Paper and Live strategies continue to use their own active policy and order paths. The candidate runs a separate instance of the existing Paper engine and has no dependency on the Live executor, AI analyzer, exchange order API, or promotion mechanism. Its independent risk budget covers position count, daily loss, aggregate open risk, available margin, exposure, consecutive losses, and a realized drawdown limit. Existing stop loss, fees, spread, slippage, minimum trade and reward/risk rules apply. Drawdown is calculated from closed trade PnL and its persisted high-water mark. The shadow engine refuses new exposure above the cap. Current adaptive governance can apply different controls to its own account, so runtime observations and controlled backtests answer different questions.

Both routes use BingX closed OHLCV and the same contract metadata. The shadow worker receives immutable candle snapshots after each normally processed 5m update, so its simulations use the same feed with a closed-time cutoff. During active ingestion, higher-timeframe candles may arrive between the two evaluations. The shadow worker has an independent bounded queue of 256 updates. When the queue overflows, the feed becomes discontinuous, or state persistence fails, shadow processing stops and reports a fault. Current Paper and Live remain independent. A faulted session can retain open virtual positions. Resume with a feed consecutive from their last stored bar, or archive the isolated file to start a new sample. Avoid interpreting periods across a data gap as uninterrupted trading.

Leave `ExperimentalStrategy:Enabled` at its default `false` until the operator is ready for a shadow run. At the next approved application startup, set `ExperimentalStrategy__Enabled=true` to enable. Available signal overrides are `MinimumAdx` (20), `MinimumAtrPercent` (0.1), `MaximumAtrPercent` (3), `PullbackBars` (3), and `MaximumEntryDistanceAtr` (1.5). Set `ExperimentalStrategy__Enabled=false` at the next approved restart to roll back. Enabling the feature does not change the Live setting.

The shadow SQLite file is stored beside the configured `Persistence:DatabasePath`, even when Current uses Supabase. Its name ends with `.shadow-trend-pullback-v1-<configuration hash prefix>.db`. Position, account and closed trade updates share the existing atomic SQLite commit. A change in the candidate, indicator, risk, MACD or simulated execution configuration gets a different file. Keep those files to preserve prior experiments. The application identity needs write access to this folder for shadow trading.

Use the existing authenticated API with `X-Api-Key`. `GET /api/bot/shadow/performance?days=90` returns the selected period and its UTC daily, Monday-based weekly and calendar monthly buckets. Valid values for `days` are 1–90, default 7. Each bucket reports:

- `marketScans`, `setupObservations` and `observedDays`. These use scan time UTC. A setup observation is a directional candidate from the signal engine, deduplicated within a UTC day by symbol, timeframe, direction, candle close and strategy configuration. Several such observations can describe one underlying market move. Guarded or unevaluated candles cannot reveal counterfactual setups. Days with trade history but no scan data report null scans/setups. `observedDays` counts calendar days with any records and does not imply a complete feed. The window starts exactly `days` elapsed days before the query, so boundary buckets can be partial.
- Closed trades, win rate, profit factor, expectancy and net PnL use the UTC close time and include only completed simulations. Win rate and expectancy are null with zero trades. Profit factor is null with zero gross loss. The closed-trade drawdown in USDT starts from zero period PnL, groups simultaneous closes, and measures the maximum peak-to-trough decline in closed trade PnL. Use replay equity or live equity observations to assess unrealized drawdown.
- Fees and funding use stored trade metrics. The combined spread/slippage estimate reverses the modeled basis-point adjustments using initial quantity and exit VWAP. It assumes all reductions had the final reduction's execution-cost rate and does not estimate gaps or market depth. These costs are already reflected in simulated trade economics. Do not subtract them again from net PnL. Cost totals are null if a closed trade lacks usable metrics, with coverage in `tradesWithCostMetrics`.

`Current` represents the existing Paper account and can span policy versions or dates before Shadow ran. `Experimental` uses the configuration hash in the response for both scans and its virtual account. Scan coverage can be shortened by diagnostics retention, a paused writer or a full queue. The response includes the process-local fallback count. Use overlapping periods with matching data, risk and cost assumptions for comparisons. For individual decisions, use signal diagnostics with mode `SHADOW`.

The isolated HTTP test can be rerun with:

```powershell
dotnet test tests/TradingBot.Tests --filter FullyQualifiedName~ShadowOnlyHost
```

This test sets a process-local and uniquely prefixed `ExperimentalStrategy__Enabled=true` environment variable on an API-only host with Live disabled. The fixture binds it through the environment configuration provider, registers only Shadow and diagnostics as bot hosted services, rejects construction of both the Live executor and the BingX market client, and injects closed candles. It checks that a virtual trade opens and closes in a separate SQLite file, then checks daily, weekly and monthly reports, duplicate setup handling, configuration hash scoping and missing scan coverage. It also injects a 5m gap and verifies that Shadow reports a fault and stops processing. The test demonstrates the isolated execution path. Sustained coverage and latency with the real public feed remain to be measured.
